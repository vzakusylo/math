# Aircraft Doppler — recovering motion from a flyby sound

An educational implementation of the **math core** behind the idea that an aircraft's
faint engine hum in a recording leaks information about the aircraft's motion.

Given only the audio of an aircraft flying by in a straight line, the code reconstructs:

* **f0** — the emitted propeller/engine fundamental frequency,
* **speed** of the aircraft,
* **slant distance** at the closest point of approach (CPA),
* the **moment of the flyby**.

> Scope: this is the signal-processing / physics core only. It does **not** perform
> geographic localization (matching curves against real ADS-B flight data to find
> *where* a video was shot). It is meant for learning how the Doppler effect encodes
> motion, not for locating anyone.

On the default synthetic scenario the recovery error is **f0 ~0.1%, speed ~0.6%,
distance ~2%** — see the demo output below.

## How it works

### The physics

A source (aircraft) moves in a straight line at constant speed `v` and passes the
microphone at a minimum **slant distance** `d` (CPA). The sound takes time to travel,
so what you hear *now* was emitted earlier.

With `c` the speed of sound, `t_e` the emission time, `t_c` the emission time at CPA:

```
r(t_e) = sqrt(d² + v²·(t_e − t_c)²)          distance from source to mic
t_a    = t_e + r(t_e)/c                       arrival time of that sound
s      = v·(t_e − t_c)                         position of source along the track

f(t_a) = f0 / (1 + v·s / (r·c))               received (Doppler-shifted) frequency
```

Far **before** the flyby the source approaches → higher pitch; far **after** it
recedes → lower pitch. The asymptotes give speed and the true pitch directly:

```
f_high = f0·c/(c − v)        f_low = f0·c/(c + v)

  v  = c·(f_high − f_low)/(f_high + f_low)
  f0 = 2·f_high·f_low/(f_high + f_low)          (harmonic mean)
```

The **steepness** of the frequency drop at the flyby fixes the distance:

```
df/dt |cpa = −f0·v²/(c·d)     ⇒     d = −f0·v² / (c · df/dt|cpa)
```

Because distance depends only on that slope, it is the **least robust** parameter —
for distant, slow, or faint passes the Doppler curve is gentle and `d` can be off by
tens of percent. Speed and f0 stay accurate. (This is exactly why the real-world
technique keeps speed/distance as wide ranges rather than precise numbers.)

### The pipeline

1. **Synthesis** (`synth.py`) — build a physically faithful flyby sound: for each
   receiver sample `t_a` solve the quadratic for the emission time `t_e`, integrate
   the emitted phase, and add geometric `1/r` attenuation, high-frequency roll-off
   with distance, several propeller harmonics, and background noise.
2. **Spectrogram** (`spectro.py`) — a long-window STFT (~1 Hz resolution) with double
   *whitening*: subtracting the median over time removes steady tones (mains hum,
   fans), subtracting the median over frequency removes broadband bursts (wind, thumps).
   The slowly drifting aircraft line survives.
3. **Ridge tracking** — a Viterbi search finds the brightest continuous curve, with a
   near-ban on rising frequency (a flyby curve only descends).
4. **Centroid refinement** — the raw spectrogram peak of a fast chirp is biased by ~1–2 Hz
   (asymmetric spectral leakage), which alone inflates speed/distance errors to 7–15%.
   An intensity-weighted centroid in a narrow band around the ridge removes this bias.
5. **Fit** (`fit_pass`) — least-squares fit of the exact straight-flyby model to the
   curve, returning f0, speed, distance, flyby time and their uncertainties.

### Package layout

```
doppler_geo/
├── demo_doppler.py        # synth → recover → compare to truth + plot  (start here)
├── doppler_flyby.py       # self-contained single-file version of the same idea
└── aerodoppler/
    ├── geo.py             # speed of sound, local ENU coordinates, distances
    ├── synth.py           # flyby audio synthesis
    ├── spectro.py         # spectrogram, ridge tracking, centroid, model fit
    ├── physics.py         # Doppler formula + closed-form straight-pass solution
    └── adsb.py            # (optional) read ADS-B tracks from CSV
```

## How to run

**Requirements:** Python 3.9+, with `numpy`, `scipy`, `matplotlib`.

```bash
pip install numpy scipy matplotlib
```

**Run the demo** (from the repo root):

```bash
cd doppler_geo
python demo_doppler.py
```

On Windows use `py demo_doppler.py`.

It prints a truth-vs-estimate table and writes `doppler_geo/doppler_demo.png`:

```
parameter              truth     estimate      ±σ      error
fundamental f0, Hz     95.00       95.07      0.02     +0.1%
speed, m/s             72.00       71.57      0.06     −0.6%
speed, km/h           259.20      257.63      0.21     −0.6%
CPA distance, m       550.00      562.75      2.50     +2.3%
flyby time, s          45.00       45.92      0.02     +2.1%
```

**Try other scenarios** — edit the `synth_flyover(...)` call in `demo_doppler.py`
(`speed`, `dist`, `f0`, `noise_db`, `seed`). The standalone `doppler_flyby.py` also
takes command-line flags:

```bash
python doppler_flyby.py --speed 60 --dist 1200 --f0 90 --snr -25
```

**Use your own recording** instead of synthetic audio: extract mono audio from a video
and feed it to the spectrogram stage.

```bash
ffmpeg -i video.mp4 -ac 1 -ar 8000 audio.wav
```

Then load it with `aerodoppler.spectro.load_audio("audio.wav")` and reuse the
`track_ridge → refine_centroid → fit_pass` steps from `demo_doppler.py`, choosing a
time/frequency window around the audible flyby.
